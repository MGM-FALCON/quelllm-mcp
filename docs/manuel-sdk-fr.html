Utiliser le serveur MCP QuelLLM : installation et référence

L’équipe QuelLLM · Référence du code 1.1.0 · Relu le 24 octobre 2026

Le serveur MCP QuelLLM donne à un client compatible accès au catalogue de modèles de QuelLLM. Il fournit six outils pour chercher un modèle, lire sa fiche, comparer des données et calculer des estimations. Ce manuel explique comment le lancer et interpréter ses réponses.

Le SDK ne télécharge pas les poids des modèles et ne lance pas leur inférence. Il interroge une source distante pour les outils de catalogue ; son transport MCP est stdio, avec un processus local qui échange sur son entrée et sa sortie standard.

1. Installer et lancer le serveur MCP QuelLLM

Le projet demande Python 3.10 ou une version supérieure. Ses dépendances déclarées sont mcp[cli]>=1.0.0,<2 et httpx>=0.27.0. Les commandes suivantes proviennent du README du dépôt ; elles installent ou exécutent du code Python depuis GitHub.

Pour installer le paquet, utilisez un environnement Python adapté à votre machine :

pip install git+https://github.com/MGM-FALCON/quelllm-mcp.git

La commande du serveur devient quelllm-mcp. Si vous utilisez déjà uv, le README propose aussi ce lancement avec uvx, qui gère l’environnement du paquet :

uvx --from git+https://github.com/MGM-FALCON/quelllm-mcp.git quelllm-mcp

Ces commandes suivent la branche par défaut du dépôt. Pour reproduire exactement une version, conservez aussi la révision du code utilisée. La référence de ce manuel est indiquée dans les sources en fin de page.

Après installation, voici la forme de configuration illustrée par le README :

{
  "mcpServers": {
    "quelllm": { "command": "quelllm-mcp" }
  }
}

Le chemin du fichier de configuration dépend de votre client MCP. Celui-ci doit pouvoir trouver la commande dans son environnement. Ce bloc n’est pas une preuve de fonctionnement sur tous les clients : aucune nouvelle recette de compatibilité n’a été effectuée pour ce manuel.

2. Choisir parmi les six outils du SDK

Commencez par une recherche ou une liste, puis reprenez les identifiants réellement renvoyés par le catalogue. Un nom commercial et un identifiant technique peuvent différer. Les paramètres ci-dessous reprennent les fonctions exposées par le code.

Sur mobile, faites défiler le tableau horizontalement pour lire les trois colonnes.

OutilEntréesUtilité et lecture du résultat
list_modelsfilter_origin, filter_family, max_params_b ; tous facultatifs.Filtrer le catalogue par origine, famille ou nombre maximal de paramètres en milliards. Les données disponibles dépendent du catalogue chargé.
search_modelsquery ; limit vaut 10 par défaut.Chercher dans le nom, l’identifiant, la famille, l’auteur et les tags. Le classement applique les règles de score du code, sans calcul d’embeddings.
get_modelmodel_id.Lire une fiche du catalogue. Un identifiant inconnu produit un objet d’erreur, pas une fiche inventée.
comparemodel_a_id, model_b_id.Comparer deux fiches, notamment leurs paramètres, leur contexte et les valeurs mémoire. Le « verdict » est une synthèse de données, pas un classement de qualité mesuré.
estimate_vrammodel_id ; quant vaut q4 par défaut.Lire la valeur mémoire du catalogue pour une quantification et produire une liste matérielle indicative. Les clés disponibles varient selon la fiche.
estimate_costinput_tokens_per_month, output_tokens_per_month ; options détaillées plus bas.Calculer un scénario API ou matériel à partir d’hypothèses intégrées au SDK. Les résultats ne constituent pas des devis actuels.

Exemple d’entrées pour search_models, à transmettre via votre client :

{ "query": "mistral", "limit": 5 }

Pour limiter ensuite une liste à 14 milliards de paramètres, les entrées de list_models peuvent être :

{ "max_params_b": 14 }

Ces exemples illustrent les paramètres ; ils n’ont pas été exécutés pour cette publication. Ils ne garantissent ni un nombre de résultats ni la disponibilité du catalogue au moment de votre appel.

3. Comprendre la source distante et le cache local

Les cinq outils de catalogue chargent https://quelllm.fr/api/models.json. Selon le dépôt, cette source ne demande pas de clé API. Le fichier est mis en cache dans ~/.cache/quelllm-mcp ; la durée de fraîcheur prévue est de 3 600 secondes, soit une heure.

Lorsqu’un cache valide est encore frais, le SDK le lit. Après expiration, il tente une requête distante. Si cette requête échoue, il réutilise le fichier de cache existant ; en l’absence de cache, il lève une erreur RuntimeError. Un résultat peut donc provenir de données plus anciennes que la durée annoncée en cas de panne réseau.

Disponibilité : l’état actuel de l’API n’a pas été validé pour ce manuel. Des contrôles antérieurs ont rencontré une restriction HTTP 403 ; aucune nouvelle requête de diagnostic n’a été lancée ici. La présence de cette documentation statique ne prouve pas que le catalogue distant répond.

Le processus MCP s’exécute localement, mais les outils de catalogue dépendent de cette source réseau. Le SDK n’est donc pas autonome hors ligne par conception. Un cache existant peut aider lors d’une indisponibilité ; il ne garantit pas des informations récentes.

4. Lire les estimations de mémoire et de coût

estimate_vram renvoie la valeur du catalogue dans vram_gb. Pour construire fits_on, le code retient les matériels de sa table dont la capacité dépasse cette valeur d’au moins 2 GB. Cette marge fixe ne mesure ni le cache KV réel, ni le pic d’allocation, ni les autres logiciels présents en mémoire.

Une entrée dans fits_on ne garantit donc pas que le modèle démarre sur votre machine. Vérifiez séparément le fichier de poids, le moteur d’exécution, le contexte, la taille de lot et la mémoire disponible. Le guide anglais sur le cache KV détaille pourquoi le contexte change le budget mémoire.

Pour estimate_cost, les deux volumes de jetons sont obligatoires. L’option model_or_hardware choisit une entrée de la table API ou matériel ; sans cette option, le code compare les scénarios disponibles.

Les autres options sont amort_months, electricity_eur_per_kwh, hours_active_per_day, caching_hit_rate, batch_mode, off_peak, pc_always_on et vat_recoverable. Elles modifient les hypothèses d’amortissement, d’énergie, de cache, de traitement ou de TVA.

Les tables de prix portent une note de fraîcheur 2026-05 dans le code. Le taux USD/EUR, les débits matériels et certaines remises sont aussi des constantes de calcul. Consultez les sources commerciales actuelles avant une décision d’achat ; ce manuel ne présente aucun prix ni débit comme une mesure récente.
